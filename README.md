##  Gift Assistant — Помощник для выбора подарка

**Прозрачный, быстрый и персонализированный сервис для выбора подарков** с использованием гибридной системы рекомендаций (правила + ML) и импортом интересов из VK.

---

##  Описание проекта

Gift Assistant — это веб-приложение, которое помогает подобрать подарок для конкретного человека с учётом:

- бюджета
- возраста и пола
- повода (День рождения, Новый год и другие)
- типа отношений (друг, партнёр, коллега, родственник)
- интересов получателя (ручной ввод или импорт из VK)
- исключений (что дарить НЕ нужно)

### Ключевые особенности

- **Rule-based фильтрация** — строгое соблюдение бюджета, возраста и исключений. Ни один товар, нарушающий обязательные ограничения, не попадает в выдачу.

- **ML-ранжирование** — градиентный бустинг (GradientBoostingRegressor из scikit-learn) для сортировки наиболее релевантных подарков. Используется гибридная формула: 70% эвристики + 30% ML.

- **Прозрачные объяснения** — к каждому подарку прилагается список причин рекомендации (например: «Соответствует интересу "космос"», «Попадает в бюджет», «Подходит для Дня рождения»).

- **Импорт интересов из VK** — по публичной ссылке на профиль без авторизации получателя. Система извлекает интересы, музыку, книги, игры, группы и маппит их на внутренний словарь.

- **Готовность к развёртыванию** — Docker Compose для запуска одной командой.

### Функциональные требования
Регистрация и аутентификация

регистрация через email и пароль (минимум 6 символов);

хранение пароля в виде bcrypt-хеша;

аутентификация через JWT (Bearer Token), срок действия 1440 минут.

Профиль пользователя и получателя

профиль пользователя: email, пароль, имя;

профиль получателя: обязательные — возраст (0–120), повод; необязательные — пол, тип отношений;

интересы: JSON-список строк, чек-листы + импорт из VK;

исключения («не дарить»): JSON-список категорий/товаров.

Импорт интересов из VK

импорт по публичной ссылке или screen_name;

извлечение данных через VK API (users.get, groups.get);

маппинг на внутренний словарь (INTEREST_MAPPING);

объединение с существующими интересами, редактирование через PATCH /recipients/{id}.

Мастер подбора подарков

входные параметры: recipient_id, бюджет (мин/макс), категории (мультивыбор), top_k (1–20);

проверка budget_min ≤ budget_max (HTTP 400 при нарушении).

Каталог товаров

импорт из CSV через POST /products/import-csv (защищён JWT);

фильтрация GET /products по цене и категории;

нормализация: категории к нижнему регистру, парсинг тегов через запятую.

Rule-based фильтрация рекомендаций

отсеивание по бюджету (budget_min ≤ price ≤ budget_max);

исключение по возрасту (age_limit ≤ recipient.age);

удаление по списку «не дарить» (по категории и названию);

фильтрация по поводу и типу отношений (если теги заданы).

ML-ранжирование рекомендаций

модель GradientBoostingRegressor (8 признаков);

fallback на чистую эвристику, если модель не загружена;

гибридная формула: final_score = 0.7 × heuristic + 0.3 × ml_score;

сортировка по убыванию score, вывод top-K.

Генерация объяснений

2–4 причины на каждый товар: соответствие интересу, попадание в бюджет, повод, тип отношений;

возврат в поле reasons карточки RecommendationItem.

CRUD профилей получателей

создание (POST /recipients), список (GET /recipients), получение (GET /recipients/{id}), обновление (PATCH /recipients/{id}), удаление (DELETE /recipients/{id});

контроль доступа: 404 если не найден, 403 если чужой.

Получение данных о пользователе

GET /auth/me — текущий пользователь по JWT;

POST /auth/login — выдача access_token с token_type: "bearer".

### Нефункциональные требования
Производительность

время ответа мастера подбора ≤ 3 сек;

загрузка главной страницы и профиля ≤ 2 сек;

локальный inference ML-модели без внешних ML-сервисов.

Надёжность

понятные сообщения об ошибках (400, 401, 403, 404);

fallback на эвристику, если ML-модель не загружена;

try_get_vk_groups возвращает пустой список, если группы скрыты.

Безопасность

bcrypt для паролей (passlib);

JWT HS256 с SECRET_KEY из env;

VK Service Token в env, не в БД;

контроль доступа к получателям через get_owned_recipient.

Конфигурируемость

все параметры через env: DATABASE_URL, SECRET_KEY, ALGORITHM, ACCESS_TOKEN_EXPIRE_MINUTES, VK_SERVICE_TOKEN, VK_API_VERSION.

Валидация входных данных

Pydantic v2: EmailStr, Field(ge=, le=, min_length=, max_length=);

age: 0–120, budget_min ≥ 0, budget_max > 0, top_k 1–20.

Нормализация данных

normalize_text — нижний регистр, удаление пробелов;

normalize_list — очистка списков;

parse_tags — парсинг тегов из CSV.

Контейнеризация и развёртывание

Docker для backend (Python 3.11 slim);

Docker Compose для совместного запуска;

SQLite + Docker volume для сохранности данных.

Тестируемость

unit-тесты на pytest (22 теста);

покрытие: нормализация, rule-based фильтры, генерация рекомендаций, объяснения.

Воспроизводимость ML

random_state=42 в обучении и валидации;

joblib для сериализации модели;

train/test split 80/20.

Расширяемость

SQLAlchemy 2.0 (Mapped, mapped_column) — замена SQLite на PostgreSQL без переписывания логики;

замена GradientBoostingRegressor на LightGBM Ranker без изменения API;

слоистая архитектура: models / schemas / routers / services / ml / core / utils.

##  Архитектура проекта

Проект реализован как классическое клиент-серверное веб-приложение.

### Основные компоненты

**Frontend (клиентская часть)**
- Назначение: пользовательский интерфейс, формы ввода данных, отображение карточек рекомендаций с объяснениями

**Backend API (серверная часть)**
- Назначение: бизнес-логика, обработка HTTP-запросов, аутентификация, фильтрация и ранжирование товаров

**ML-подсистема**
- Технологии: scikit-learn (GradientBoostingRegressor), joblib, numpy
- Назначение: загрузка обученной модели, формирование вектора признаков, расчёт ML-оценки релевантности

**Сервис интеграции с VK**
- Технологии: requests, VK API 
- Назначение: импорт публичных интересов из профиля VK по ссылке

**База данных**
- Технологии: SQLite (прототип), SQLAlchemy ORM
- Назначение: хранение пользователей, получателей, товаров, интересов

**Инфраструктура**
- Технологии: Docker, Docker Compose
- Назначение: контейнеризация и унифицированный запуск всех компонентов

### Паттерны проектирования

- **REST API** — слабосвязанное взаимодействие клиента и сервера через HTTP-методы (GET, POST, PATCH, DELETE) с передачей данных в JSON.

- **MVC + Service Layer** — разделение ответственности: модели (ORM), контроллеры (routers), бизнес-логика (services), инфраструктура (core).

- **Pipeline (конвейер)** — последовательная обработка запроса рекомендаций: фильтрация по правилам → ML-ранжирование → формирование объяснений.

##  Инструкция по запуску

### Шаги для запуска

Перейдите в папку проекта:

cd gift-assistant-mvp

запустите :
docker compose up --build

открыть сайл http://localhost:5173/dashboard , зарегестрироваться , загрузить каталог подарков products.csv , и заполнить данные о получателе, можно импортировать из его вк интересы
